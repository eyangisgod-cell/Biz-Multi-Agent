4.2 可靠性需求
●LLM 调用成功率 > 99%（含重试机制），单次模型故障不影响系统可用性。
●数据采集失败自动重试 3 次，仍失败则跳过并记录告警，不阻塞整体流程。
●RAG 检索为空时，Agent 应回退到纯 LLM 推理并标注「无知识库依据」，不报错中断。
●系统异常不丢失任务状态，支持从断点恢复（AgentScope Pipeline Checkpoint）。
4.3 安全需求
●所有 API Key 通过环境变量注入，不硬编码，不提交到 Git。
●用户输入做 SQL 注入和 Prompt 注入防护，LLM 输出做内容过滤。
●Web 后台基础鉴权（JWT），API 接口限流防滥用。
●日志脱敏，客户隐私数据（手机号、邮箱）不记录明文。
4.4 可维护性需求
●代码分层清晰：表现层 / 编排层 / Agent 层 / 服务层 / 数据层，层间通过接口通信。
●业务逻辑与框架代码分离，切换 AgentScope 版本不影响业务代码。
●所有配置外置，支持热更新，修改 Prompt 不需要重启服务。
●完整 README + 架构文档 + API 文档 + 部署文档，新人 1 天可上手。

5.1 功能验收标准
MVP 交付时，以下场景必须可完整演示，每个场景都有明确的验收标准：
5.1.1 电商选品场景验收
1. 用户在 Web 后台输入选品关键词（如「蓝牙耳机」）和目标平台（如美客多）。
2. 系统自动触发 4 个 Agent 协作：采集 Agent 获取商品数据，RAG Agent 检索平台规则，评估 Agent 评分排序，汇总 Agent 生成报告。
3. 120 秒内输出完整选品报告：Top 20 候选商品清单、评分明细、市场分析、营销建议。
4. 报告可导出为 Markdown 和 PDF 格式，JSON 数据可通过 API 获取。
5. 全程可在 AgentScope Studio 查看调用链路，每个 Agent 的输入输出可追溯。
5.1.2 外贸询盘场景验收
1. 系统接收模拟询盘消息（WhatsApp/邮件格式），自动解析客户意图和关键信息。
2. 15 秒内完成客户分层（A/B/C 级），匹配跟进策略。
3. 自动生成多语言报价单（PI），B 级以上需人工确认后发送。
4. 客户信息和询盘记录结构化存储到 SQLite，可在后台查询。
5. 定时跟进任务自动创建，到时间触发邮件发送。
